# The workflows' actions pinned to a commit, their token read-only (#137)

- **Decision:** every `uses:` in `.github/workflows/` names a commit, with its version after `#`: `actions/checkout` v4.4.0, `actions/setup-node` v4.4.0, `subosito/flutter-action` v2.23.0 and `maxim-lobanov/setup-xcode` v1.7.0, the same code the tags `v4`, `v2` and `v1` pointed to on 4 Nov. A new action or a new version goes in the same way, as the commit of a release tag in the action's own repository, and arrives through a pull request like any change. Each workflow also sets `permissions: contents: read`, so the run's GitHub token reads the code and can change nothing. Replaces the moving tags (`@v4`, `@v2`, `@v1`) and the token's rights from the repository's setting.
- **Why:** S3 of the release audit (`handoff/audit-2026-11-04.html`, 4 Nov). Whoever controls an action's repository can move its tag to other code, and the next run takes it unseen. In the TestFlight run that code would sit beside the App Store Connect key, the Distribution certificate and the sandbox chat key, and in the deploy beside the Cloudflare token. A commit cannot change. The two outside actions, `subosito/flutter-action` and `maxim-lobanov/setup-xcode`, are each one person's repository. Roman, 4 Nov: «Да, S3».
