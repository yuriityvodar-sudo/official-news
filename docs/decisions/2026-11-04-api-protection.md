# The API behind a rate limit, at api.outernews.app (#137)

- **Decision:** the API Worker answers at `https://api.outernews.app`, a custom domain of the zone `outernews.app`, as the website and the admin page do. TestFlight builds use that address from now on (`testflight.yml`). The Worker limits each address to 300 requests a minute in a Cloudflare location (`API_LIMIT`, Workers Rate Limiting). Past that it answers `429` with `Retry-After: 60` before anything reads D1. Apple's notifications and requests without an address are never limited. In front of the Worker, the zone's one free rate limiting rule blocks an IP that makes more than 100 requests to `api.outernews.app` in 10 seconds, for 10 seconds; Yurii or Roman creates it in the dashboard (`docs/setup.md`). `api.officialnews.workers.dev` stays on until the team's builds and Apple's notifications use the new address, then goes off before the release (`workers_dev`), so nothing can reach the Worker past the zone's rule.
- **Why:** S2 of the release audit (`handoff/audit-2026-11-04.html`, 4 Nov). On the Free plan the Worker stops for everyone after 100,000 requests a day (error 1027 until 00:00 UTC), and requests with made-up `cursor` or `since` values miss the cache and each read D1. D1's 5 million rows a day are the fetcher's too: crawlers used them up on the website in two hours on 30 Oct. workers.dev cannot have a zone's rules. The Worker's own limiter protects D1. Only the zone's rule protects the day's requests, and only against floods from a few addresses; against very many, Workers Paid ($5 a month) is the way out, a decision for both of us. Roman, 4 Nov: «закрывай все блокеры».
- **Status:** Proposed (Roman's Claude, on Roman's word of 4 Nov)
