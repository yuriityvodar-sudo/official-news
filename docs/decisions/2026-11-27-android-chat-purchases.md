# Android: the AI chat is bought on Google Play, checked by the server with Google

**Decision (27 Nov 2026, #349).** On Android the chat's subscription and its two packs are sold through Google Play under the same product ids as on the App Store (`com.officialnews.app.agent.monthly`, base plan `monthly`, $4.99; `…questions50` $0.99; `…questions200` $2.99; created 27 Nov on Yurii's Play account). The app sends what Google Play gives it in the same `transaction` and `pack` fields, marked `gp:` (`gp:<purchaseToken>`, `gp:<productId>:<purchaseToken>`). Google's tokens are not signed for us, so the server asks Google's Play Developer API about each one (`server/src/googleplay/`) with its own read-only robot (`PLAY_SERVICE_ACCOUNT`), acknowledges a new subscription and consumes a pack once credited. Everything after that is the iPhone's code unchanged: one `subscriptions` row per Google subscription (its first order id, `gp:GPA.…`, the same across renewals), the same week, packs, wallet and Sandbox rules; Google's test purchases count as Sandbox.

**Why.** One server path keeps the limits and the cost the same on both platforms (Roman's weekly usage, #146), with no new tables. Asking Google on each check (one call, cached access token) replaces Apple's signed transactions and notifications: a refund shows as `SUBSCRIPTION_STATE_REVOKED` at the next question. Google's Real-time developer notifications (Pub/Sub) can come later if needed. Roman agreed on 17 Nov that the Android part of #146 is Yurii's.

**Status.** Server part in this pull request; the app side (Google Play in the chat screen, texts naming Google Play) follows in its own pull request.
