# Decisions

Newest first. Every decision that changes how we build goes here, through a pull request, with its date and reason. "Proposed" means waiting for the other person's confirmation.

| Date | Decision | Why | Status |
| --- | --- | --- | --- |
| 2026-10-15 | The feed is ordered by when each decision appears in it (`feed_seq`, a number given when the AI marks it visible, only rising, never changed), not by publication time; cards still show the official publication date. Paging and the "N new" check (`after=<feedSeq>`) use the same number. Replaces the ordering by `published_at` (2026-10-14) and the "show the latest published items by date" part of 2026-10-11 | Live data: 12 of 25 decisions overnight appeared in the middle of the feed under publication-time order, and the "new" check missed them. Research (docs/research/2026-10-15 Feed ordering for late items.md): FreshRSS, Inoreader, Feedly, Hacker News, X and Mastodon order by arrival; Bluesky, ordered like we were, documents the same blind spot. The number also leaves room for syncing to the phone and "For you" later | Agreed |
| 2026-10-14 | AI summaries run on Workers AI, model `@cf/zai-org/glm-4.7-flash`, with reasoning off and a JSON schema for the answer. Rules in `docs/style-guide.md`; the model is one constant (`MODEL` in `server/src/summarizer/index.ts`). A run claims its articles before calling the model (`summary_claimed_at`, migration `0005`; a claim older than 10 minutes no longer counts) | Roman (item 7): no API key and no bill to start; the model reads 100+ languages, takes long texts, and at about 60 to 70 Neurons per article the free 10,000 Neurons a day cover roughly 150 articles. Claude or a larger model stays an option if quality needs it | Agreed |
| 2026-10-14 | Fetcher rules (item 6): user agent `OfficialNewsBot/0.1 (+repo URL)`; robots.txt is checked before every list and item page (4xx means no rules, 5xx or no answer means skip the source this time); only the last 7 days are saved; per check at most 20 newest items looked at and 10 new saved; per run at most 4 item pages and 40 requests; text kept 30 days; sources with `conditionalGet` send back the server's ETag / Last-Modified (two new `sources` columns) and skip the download on 304; a run claims its sources first; only https links on the source's own site are kept; undated items are skipped and no time is later than the fetch; Kickoff seed and `blocked` sources are never fetched | Stays inside the free plan (50 requests, 10 ms CPU per run) and never saves items the feed would not show, so no AI calls are wasted on them | Agreed |
| 2026-10-14 | Official gazettes are allowed as sources, with a title pre-filter (`exclude` in the source config) that drops routine entries (rates, price indices, edicts, company notices, tenders, routine appointments, technical standards) before the AI step. Sources are read over `https` only. A source removed from `docs/sources.csv` is set to `blocked` when the list is loaded | Roman (review of #26): gazettes are where decisions take effect, but routine entries would cost AI calls; plain http can be altered on the way | Agreed |
| 2026-10-14 | Source list (item 5): 19 official decision sources in `docs/sources.csv`, one per G20 member except Saudi Arabia, whose only reachable official source (the Umm al-Qura gazette) forbids automated monitoring without written consent. The deploy loads the CSV into D1 on every change; Kickoff seed sources stay in D1 and the fetcher and health checks skip them. Open points and backups in `docs/sources.md` | Decisions-only rule: the 11 Oct test sources were mostly statements, so every source was researched again and checked live on 14 Oct (official, robots.txt, no bot check, decisions) | Agreed |
| 2026-10-14 | No shared password vault (Bitwarden dropped): a key never travels between us. Whoever creates a key puts it straight into its one home. Only Yurii, as repo owner, can add GitHub Secrets, so he creates the keys CI needs himself; the App Store Connect API key he creates with his Admin role on Roman's Apple team. Cloudflare Worker secrets are set by whoever creates the key | Roman: simpler, and nothing secret is ever handed over | Agreed |
